# Simulator catalog and synchronized performance milestone

Date: 2026-09-10

The Rev D Eyes controller, Mouth controller, Brain, and Audio FX board have now
completed the first end-to-end performance generated by Bender Expression Lab.
This establishes the working content path from authored simulator frames to
button-triggered physical playback.

## Validated behavior

- The simulator exports separate Eyes, Mouth, Performance, Audio, and Audio FX
  deployment catalogs for the Rev D development geometry.
- Audio events retain stable semantic IDs while the deployment manifest maps
  the installed subset onto `T00.WAV` through `T99.WAV` slots.
- A build-time converter generates compact CircuitPython modules. Display
  controllers do not parse the larger JSON exports at runtime.
- Both display controllers can browse their exported content locally in
  Bender mode and accept named animation commands in Target mode.
- The Brain Play menu browses exported performances first and individual Eye
  and Mouth animations afterward.
- `PLAY_ANIMATION_TIMED` gives each controller an entry, hold, and exit duration
  in milliseconds. Controllers retime authored frames locally at no more than
  the exported maximum display FPS, leaving I2C free between semantic events.
- The Brain schedules display and Audio FX events from the exported performance
  timeline. Performance 0 played both displays and `T00.WAV` with timing
  reported as visually close on the assembled hardware.
- The controller Normal Eye frame reserves the top two and bottom two rows for
  later shocked/visor movement.

The current hardware result is sufficient to validate the architecture. Exact
inter-controller and audio skew still needs measurement using high-speed video
or logic-analyzer traces before timing tolerances are finalized.

## Deployment safety

Do not trust macOS volume names such as `CIRCUITPY 1`: suffixes can be reassigned
when several boards reboot. Before every installation, read `boot_out.txt` and
match both board type and UID. Install boards sequentially, copy support/data
files first, and copy `code.py` last because writing it triggers a reboot.
